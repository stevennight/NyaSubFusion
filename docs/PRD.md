# NyaSubFusion 产品需求文档（PRD）

> 版本 v0.2（草案）· 2026-10-16　·　v0.2：注音跟随图层语言；多目标语言图层；安装包拆分；桌面壳定为 Tauri 2
> 配套：[技术设计 DESIGN.md](DESIGN.md) · [交互原型 prototype/index.html](../prototype/index.html)

---

## 1. 背景

前身 `subfusion` 是一个命令行工具，解决一个很具体的问题：**NHK 纪录片外挂字幕不全**——方言采访只烧在画面上，甚至一句话半句在外挂字幕、半句在画面字上。它把三路信息融合后交给大模型翻译，效果已经验证可行：

```
外挂字幕(文字最可信) ─┐
画面字 OCR(补缺)     ─┼─► 规则融合 ─► 大模型合并/纠错/翻译 ─► 双语 ASS
语音 ASR(定时间/补漏) ─┘
```

但它的局限也很明显：

| 问题 | 表现 |
|---|---|
| 场景写死 | 默认日→中、默认纪录片、prompt 里写死 NHK 节目信息 |
| 没有界面 | 只能拖文件到 `.bat`，所有调参都靠改 TOML，结果好坏只能打开播放器看 |
| 不能审校 | 识别错了、融合错了、翻译错了，只能改中间 JSON 或重跑 |
| 输出固定 | 只有「中文 + 小字日文」一种排版，不能单独配原文 / 译文，没有注音 |
| 断点靠“脏标记” | 改一个参数常常要整段重做，不知道哪些步骤受影响 |

## 2. 产品定位

**NyaSubFusion：通用、可视化、可配置的多源字幕生成与翻译工作台。**

- **通用**：任意源语言 → 任意目标语言；纪录片、动画、综艺、讲座、MV 都有对应预设。
- **多源**：音频（ASR）、画面字（OCR）、自带字幕（外挂 / 内封 / 广播字幕 / 图片字幕）三路任意组合，有几路用几路。
- **可视化**：从导入、流程、审校到样式、导出全部在界面里完成，所见即所得。
- **可配置输出**：字幕由「图层」拼成——原文、译文、注音（振假名 / 拼音 / 罗马字）、说明、译注，每层独立开关和样式；一次可导出多套方案。

一句话：**把“识别 → 融合 → 翻译 → 注音 → 排版 → 导出”做成一条可视、可调、可审的流水线。**

## 3. 目标用户与场景

| 用户 | 典型场景 | 关心什么 |
|---|---|---|
| 个人搬运 / 字幕组 | 日本纪录片、综艺：外挂字幕缺台词，画面字多 | 漏句少、画面字不被遮、术语统一 |
| 语言学习者 | 日剧带振假名、中文视频带拼音、双语对照 | 注音准确、可选“只注难字”、样式好看 |
| 无字幕视频 | 讲座、播客、Vlog | 只有音频 → ASR + 翻译，断句好 |
| 只有硬字幕 | 老片、网络视频 | OCR 提取为软字幕，再翻译 |
| 已有字幕 | 生肉字幕 / 官方字幕 | 只要翻译 + 注音 + 重新排版 |
| 视频创作者 | 自己的视频做多语字幕 | 批量、多语言、硬字幕压制 |

## 4. 核心概念

| 概念 | 说明 |
|---|---|
| **来源 Source** | `字幕`（外挂/内封/广播/图片字幕）、`画面字`（OCR）、`语音`（ASR）。每路可开关、可设可信度权重 |
| **候选条目 Candidate** | 各来源识别出的原始条目，带时间、文字、置信度、画面位置等 |
| **融合 Fusion** | 规则 + 大模型，把候选条目整理成最终字幕条：去重、拼半句、纠错、分类 |
| **字幕条 Cue** | 统一数据：时间、类型（台词/旁白/说明/人名条/标题/歌词/音效）、原文（带分词与读音）、译文、说话人、来源追溯、审校状态 |
| **图层 Layer** | 一条字幕输出时的组成部分。每层 = **角色**（原文 / 译文 / 整行转写 / 说明 / 译注）× **语言**。注音跟着这一层的语言走，原文和译文都能加 |
| **语言包 Language Pack** | 一门语言的分词、注音、转写、断行、标点规则。某层能选哪些注音，由它的语言包决定 |
| **输出方案 Profile** | 一组图层 + 样式 + 文件格式 = 一个输出文件。一次可勾选多个方案同时导出 |
| **预设 Preset** | 按内容类型打包的推荐参数（OCR 区域、ASR 模型、翻译风格、样式） |
| **作品 Series** | 多集共享的节目说明、术语表、翻译风格、样式；第 2 集起自动继承 |

## 5. 功能需求

优先级：**P0** = 第一个可用版本必须有；**P1** = 正式版；**P2** = 之后。

### 5.1 导入与项目

| ID | 需求 | 优先级 |
|---|---|---|
| IN-1 | 拖入视频 / 音频文件或文件夹；支持 mp4/mkv/ts/m2ts/mov/webm、mp3/wav/flac/m4a | P0 |
| IN-2 | 自动探测：同名外挂字幕、内封文字字幕轨、ARIB 字幕 / ARIB-TTML 数据流、图片字幕轨（PGS/VobSub/DVB），显示在导入页供勾选 | P0 |
| IN-3 | 选择源语言（可自动检测）、目标语言（可多选）、内容预设、所属作品 | P0 |
| IN-4 | 为浏览器不能直接播放的视频（TS/HEVC 等）自动生成低码率预览代理和音频波形 | P0 |
| IN-5 | 批量队列：多个文件按同一配置排队处理，可暂停/重排 | P1 |
| IN-6 | 只导入字幕文件（无视频）：做翻译 + 注音 + 重排版 | P1 |

### 5.2 识别

**语音 ASR**

| ID | 需求 | 优先级 |
|---|---|---|
| ASR-1 | 本地引擎：faster-whisper（large-v3 / turbo / kotoba-whisper 等），GPU 可选 | P0 |
| ASR-2 | 逐词时间戳；VAD 门槛可调（小声采访默认放宽）；幻觉句过滤（按语言维护列表） | P0 |
| ASR-3 | 云端 ASR 引擎插件（OpenAI 兼容 / 其他服务） | P1 |
| ASR-4 | 说话人分离（diarization），结果作为字幕条的“说话人”字段 | P2 |
| ASR-5 | 人声分离预处理（BGM 大的综艺、MV） | P2 |

**画面字 OCR**

| ID | 需求 | 优先级 |
|---|---|---|
| OCR-1 | 整片按帧率扫描 → 逐帧 OCR → 跨帧跟踪 → 合并多行事件；横排、竖排都支持 | P0 |
| OCR-2 | **可视化框选识别区域**（可多个区域、可设排除区域，如台标），实时在样帧上显示识别框 | P0 |
| OCR-3 | 引擎可选：RapidOCR / PaddleOCR；按语言自动选识别模型 | P0 |
| OCR-4 | 视觉大模型复核（VLM）：纠错 + 判断“实物上的字”（招牌、包装）并丢弃 | P1 |
| OCR-5 | 每条画面字保存截图，审校时可对照 | P0 |
| OCR-6 | 图片字幕轨（PGS/VobSub/DVB）走 OCR 转成文字字幕 | P1 |

**自带字幕**

| ID | 需求 | 优先级 |
|---|---|---|
| SUB-1 | 读取 srt/ass/ssa/vtt/ttml；自动识别编码 | P0 |
| SUB-2 | 去掉自带字幕里的振假名小字（按字号比例）、说话人标记可选保留 | P0 |
| SUB-3 | 与语音自动对时：整体偏移 + 分段漂移校正 | P0（整体）/ P1（分段） |

### 5.3 融合

| ID | 需求 | 优先级 |
|---|---|---|
| FU-1 | 规则融合：画面字与字幕去重；画面字分类（台词 / 说明 / 人名条 / 标题）；台标、杂讯过滤；没被覆盖的语音单独成条，有冲突的作为“语音参考”附到条目上 | P0 |
| FU-2 | 各来源可信度权重可调（例如：没有官方字幕时，画面字 > 语音） | P0 |
| FU-3 | 大模型融合：拼回半句、纠正 OCR/ASR 错字、统一术语（与翻译同一步或单独一步） | P0 |
| FU-4 | 每条输出带**置信度与问题标记**（来源冲突、OCR 低置信、仅语音、阅读速度过快……），进入审校队列 | P0 |
| FU-5 | 时间轴精修：起止吸附到语音词边界、镜头切换点（场景切换前后不跨镜头）、最短/最长时长、相邻间隙闭合 | P1 |
| FU-6 | 融合规则可视化调试：时间轴上显示每路候选和最终结果的对应关系 | P0 |

### 5.4 翻译

| ID | 需求 | 优先级 |
|---|---|---|
| TR-1 | 任意 OpenAI 兼容接口（OpenAI / Claude / DeepSeek / 通义 / OpenRouter / 本地 Ollama），可配多个并指定用途（翻译、复核、视觉） | P0 |
| TR-2 | 两遍流程：先生成**本集概要 + 术语表**，再分段翻译（段间带上文） | P0 |
| TR-3 | 作品级设置：节目说明、术语表、翻译风格（口语/书面、敬语处理、人名译法）跨集继承 | P0 |
| TR-4 | 多目标语言：同一项目一次翻成多种语言；一个输出方案里可以放多个译文层（如中 + 英） | P1 |
| TR-5 | 单条/选中范围重新翻译，可附加指令（“更口语一点”）；给出 2~3 个候选 | P0 |
| TR-6 | 质检遍：一致性（术语、人名）、长度超限、漏译、数字错误检查 | P1 |
| TR-7 | 导出任务文件交给外部助手（如 Claude Code）翻译，再导回（保留前身的离线模式） | P1 |
| TR-8 | 翻译记忆：已审校的句子作为后续集数的参考 | P2 |

### 5.5 注音与注释（重点）

| ID | 需求 | 优先级 |
|---|---|---|
| RB-0 | 注音 / 转写由**图层的语言**决定，不区分原文还是译文（如英→日时，日语译文也能加振假名）；选项由语言包提供，界面自动生成 | P0 |
| RB-1 | 日文**振假名**：分词 + 读音 + 汉字/送假名对齐，输出为逐词的 ruby 数据 | P0 |
| RB-2 | 注音范围：全部汉字 / 只注难读字（按常用汉字表、JLPT 级别、词频阈值）/ 只注专有名词 / 每个词只在首次出现时注 / 关闭 | P0 |
| RB-3 | 注音文字：平假名 / 片假名 / 罗马字 | P0 |
| RB-4 | 读音来源优先级：用户词典 > 术语表读音（大模型给出） > 分词器；人名地名、多音字可在审校里点字修改并“记住” | P0 |
| RB-5 | 中文**拼音**（带调号/数字/不带调）、注音符号；多音字按词组判断 | P1 |
| RB-6 | 更多语言包：粤拼、韩文罗马字、西里尔 / 泰文 / 阿拉伯文拉丁转写（阿拉伯文需从右往左排版）；英文等默认无注音 | P2 |
| RB-7 | 整行转写作为独立图层：可转写原文或任一译文层（罗马字、整行拼音…） | P1 |
| RB-8 | 译注：大模型或人工为文化梗、双关添加注释，可显示在画面顶部或单独成条 | P2 |

### 5.6 审校编辑器

| ID | 需求 | 优先级 |
|---|---|---|
| ED-1 | 视频预览 + 实时叠加字幕（按当前图层配置渲染，含注音） | P0 |
| ED-2 | 多轨时间轴：波形、字幕 / 画面字 / 语音 三路候选轨、融合结果轨、译文轨；拖动调整起止 | P0 |
| ED-3 | 字幕列表：时间、类型、原文、译文、来源标签、问题标记；可按“需审校”筛选 | P0 |
| ED-4 | 检查面板：并排显示该条的所有来源（含画面字截图、语音参考），原文/译文可编辑，读音可点字修改 | P0 |
| ED-5 | 拆分、合并、改类型、改说话人、插入、删除；撤销/重做 | P0 |
| ED-6 | 快捷键：空格播放、J/K 上下条、Enter 编辑、Ctrl+R 重译 | P1 |
| ED-7 | 叠加显示 OCR 识别框、安全区域 | P1 |

### 5.7 图层与样式

| ID | 需求 | 优先级 |
|---|---|---|
| LY-1 | 图层：原文、译文（可多个，各选一个目标语言）、整行转写、说明译文、译注。每层：语言、开/关/自动、注音、字体、字号、颜色、描边、阴影、位置、行宽 | P0 |
| LY-2 | 图层顺序可拖动（译文在上 / 原文在上） | P0 |
| LY-3 | 原文显示“自动”：画面上已有原文硬字幕时不重复显示原文（前身的 `bilingual=auto`） | P0 |
| LY-4 | 避让：字幕与画面原有硬字幕重叠时自动上移；说明类画面字的译文贴在原文旁边 | P0 |
| LY-5 | 按语言的排版规则：每行字数、最多行数、标点规范（中文句末去标点、句中逗号换空格等，可选）、日文禁则 | P0 |
| LY-6 | 按类型的样式：旁白、说明、人名条、歌词、音效各自可设样式 | P1 |
| LY-7 | 样式预设导入导出；作品级共享 | P1 |

### 5.8 导出

| EX-2 | SRT：单语 / 多行双语；注音降级为括号形式 `漢字(かんじ)` 或不输出 | P0 |

## 6. 非功能需求

- **本地优先**：识别全部可在本机完成；只有翻译 / VLM 复核需要联网，且用户可见发送了什么。API Key 存系统凭据库，不写进项目文件。
- **性能**：1 小时 1080p 视频，RTX 3060 级显卡上，识别 + 融合 ≤ 15 分钟；无 GPU 时可用但会提示预计时间。
- **可恢复**：任何一步失败不丢之前的结果。
- **可扩展**：ASR / OCR / LLM / 语言包 / 导出格式都是插件。
- **平台**：Windows 优先，macOS / Linux 可运行；也可以作为服务跑在有显卡的机器上，用浏览器远程访问。
- **安装体积**：模型不进安装包。基础安装包（CPU 可用）控制在几百 MB；GPU 加速组件（CUDA 运行库，约 1~1.5 GB）和模型都在设置页按需下载，和程序分开更新。
- **界面语言**：简体中文优先，预留多语言。

## 9. 待定问题

1. ~~桌面壳用 pywebview 还是 Tauri？~~ —— **已定 Tauri 2**：自动更新、托盘、通知、文件关联、安装包都有现成方案；Python 内核作为 sidecar。开发阶段在浏览器里跑，M4 才接入桌面壳（见 DESIGN 第 10 节）。
2. ASS 注音靠逐字定位实现，播放端字体不一致会错位。是否默认把字体封装进 MKV，或推荐压制？
3. “难读字”的判定标准：常用汉字表 + JLPT 词表是否足够，是否需要用户自定义“已掌握词表”？
4. 大模型融合与翻译合在一步（省调用、上下文好）还是拆两步（可单独审原文）？—— 建议默认合并，提供“先整理原文、审校后再翻译”的两步模式。
